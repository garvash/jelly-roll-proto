- **The strip is a one-way door.** Once Phase 31.5 lands, reintroducing any cut ability requires re-authoring the schema group, presets, code, and tests from scratch. Phase 30 and 32 chose the single-fusion prototype scope deliberately; the strip enforces the choice by making backslide expensive.
- **"Bubble shield" is not a tuning group.** 32-CONTEXT D-02's "ram, charge_shot, boost, bubble_shield" is the design-doc's enumeration vocabulary; the actual schema has 4 cut groups (`dash`, `slime_ram`, `charge_shot`, `boost`) plus 2 stray cut keys in surviving groups. Bubble shield is purely code state.
- **`dash` schema group strip is independent of the Slime Ram cut ability** but coupled by V-button bind. Dash is a v1.0 mechanic that pre-dated fusion abilities; it survived into v1.3 as a Player-method (`start_dash`) and got bound to V (the same key Slime Ram uses while fused). Stripping dash and ram together is correct because they share the V binding — but they're distinct mechanics, not a single cut.
- **`_v1.3-reference.json` IS rewriting territory.** The v1.3 BEHAVIORAL spec lives in `FUSION-DESIGN.md` § Drill-Dive Contract, which is immutable under lock. The preset *file* is editable where current tuning needs require. 32-CONTEXT D-03's specifics are clear on this: "the v1.3 *behavioral* baseline is captured in FUSION-DESIGN.md Drill-Dive Contract; the preset file is a tuning artifact, not a historical archive."
- **Verification gates are sequential, not parallel.** Gate 4 (pytest) only runs once Gate 3 (smoke playthrough) passes — because pytest depends on Plan 05 being finished, and the smoke checklist signs off Plans 01-04 first. Don't run pytest mid-strip; the cut-ability test files would still be present and either fail (because the surrounding code is gone) or pass (because they test code that hasn't been deleted yet) — neither is signal.
- **Plan 03 (schema + presets) is one commit, not six.** Schema and 5 preset files share a single coherent meaning ("the 4 cut groups don't exist"). Splitting introduces a bisect window where the schema disagrees with a preset and `set_value` raises KeyError mid-game. Atomicity matters here.
- **The `Fuse` panel tab name is contentious.** Post-strip, `Fuse` routes only `drill` + `fusion` groups. Renaming to "Drill" would be honest but breaks symmetry with `FUSION-DESIGN.md` vocabulary ("fusion lifecycle", "fuse_start" event). Default: keep "Fuse"; defer rename to Phase 33+ if user playtests find it confusing.
