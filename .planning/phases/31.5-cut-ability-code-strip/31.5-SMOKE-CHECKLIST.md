# Phase 31.5: Cut-Ability Code-Strip — Human Smoke Checklist

**Purpose:** Gate 3 of CONTEXT D-18's four-gate proof-of-work. Confirm the
strip didn't break any surviving gameplay path. After Plans 01-04 deleted
ram / boost / dash / bubble shield / charge shot / Hold / cut pickups /
cut input bindings / cut tuning groups, this checklist verifies the
**surviving** systems (walk, jump, wall-jump, kick, spit, drill, mana
shield, save/load) still work.

**Why human-driven (CONTEXT D-19):** Pyxel MCP `play_and_capture` could
automate input-driven smoke, but designing the input script is itself work
outside a strip phase. Defer automation to Phase 35+.

**Companion artifact:** Results recorded in `31.5-VERIFICATION.md` Gate 3
section after sign-off.

## Run instructions

1. Boot the game: `python main.py`
2. Execute each of the 8 actions below in order; tick each checkbox.
3. If any action fails: capture the failure mode in the Notes section,
   STOP, and report back so the regression can be fixed before Phase 32
   unblock.
4. Sign off in the Sign-off section at the bottom.
5. Update `31.5-VERIFICATION.md` Gate 3 status to PASS or FAIL with notes.

## Actions

- [ ] **1. Boot game** — Title screen renders without crash. No
      `KeyError`, `AttributeError`, `JSONDecodeError`, or `ImportError` in
      stdout. Default preset loads. Room 0 is reachable from the title.

- [ ] **2. Walk left/right** — Press `LEFT` / `RIGHT` (or `A` / `D`).
      Player moves at expected walk speed. No jitter. No stuck state. Run
      animation plays.

- [ ] **3. Jump** — Press `SPACE` (jump). Player jumps. Releasing `SPACE`
      early reduces jump height (variable jump). Coyote time (jump after
      walking off ledge) and jump buffer (press jump just before landing)
      both feel preserved.

- [ ] **4. Wall-jump** — Run into a wall while airborne. Player enters
      wall-slide state (slow descent against the wall). Press `SPACE`
      while wall-sliding. Player wall-jumps in the opposite direction
      with a horizontal kick.

- [ ] **5. Kick a block** — Recall the slime (Z hold) onto a kick-target
      block (a block intended to be kicked away). The slime kicks it. The
      block animates and triggers its expected effect (e.g., destruction,
      switch trigger). Verifies the surviving spit/kick mechanic.

- [ ] **6. Spit while unfused** — While unfused, press `Z` (spit). The
      slime fires a spit projectile from its position. Projectile arcs
      and disappears on impact or off-screen. (Cross-Cutting Invariant
      #2: spit code path survives.)

- [ ] **7. Drill into CRACKED_V with full juice** — While airborne with
      `has_drill = True` and `slime.juice > 0`, hold `DOWN` and press
      `SPACE` (DOWN+SPACE per Phase 30 ground-pound input). Player enters
      `DIVING` state, drills through a CRACKED_V tile, breaks it, and
      exits cleanly when juice runs out OR ground is hit. (Cross-Cutting
      Invariant #1: drill paths survive.)

- [ ] **8. Save + reload round-trip** — Touch a SavePoint to save (the
      prompt should read "SAVED!"). Quit the game (`ESC` to title or
      close window). Relaunch `python main.py`. Load the save from the
      title. Player's `has_drill` flag is preserved; `max_hp`,
      `max_juice`, collected_iids, visited_rooms all match the pre-quit
      state. (Cross-Cutting Invariant #6: save format `version: 1`
      preserved; D-22/D-23.)

## Critical sub-actions

These are not numbered actions but invariants to confirm during the run
above (per RESEARCH § Manual-Only Verifications):

- [ ] **Mana shield (Cross-Cutting Invariant #5)** — While fused with
      `slime.juice > 0`, take damage from any hazard. Slime juice should
      drain by `MANA_SHIELD_COST`; player HP should remain unchanged.
      Verifies the bubble-shield strip didn't accidentally break the
      separate mana-shield damage path.

- [ ] **Save load with stale flags (D-23)** — If a pre-strip save exists
      on disk: load it. Stale `has_dash` / `has_shield` / `has_shield_t2`
      / `has_boost` keys in the JSON are ignored downstream because Player
      no longer reads them. Confirm: no crash on load; player's
      `has_drill` is preserved correctly.
