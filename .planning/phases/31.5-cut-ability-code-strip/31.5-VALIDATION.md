> Per-phase validation contract for feedback sampling during execution.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest + Pyxel MagicMock harness (existing — `tests/conftest.py`) |
| **Config file** | none — pytest auto-discovers `tests/test_*.py` |
| **Quick run command** | `python -c "import src.entities.player; import src.entities.slime"` |
| **Full suite command** | `python -m pytest` |
| **Estimated runtime** | Quick: <1s · Full: ~5-15s |

**Rationale for "import smoke" as the quick check:** Plan 01 sub-steps delete methods from `player.py` and `slime.py`. Module-import resolves all top-level names; if any half-stripped reference survives, import raises. Faster than pytest, broader signal than a single-line `python -c`. Pytest mid-strip is anti-signal because cut-only test files are still on disk.

## Sampling Rate

| Boundary | Sampler | Latency |
|----------|---------|---------|
| **Per task commit** (within a plan) | `python -c "import src.entities.player; import src.entities.slime"` | <1s |
| **Per plan commit** — Plans 01, 02, 04 | `python main.py` boots to title → Ctrl-C (Gate G2 partial) | ~5s |
| **Per plan commit** — Plan 03 (schema + presets) | Boot smoke + `python -c "from src.core import tuning; assert not hasattr(tuning, 'DASH_SPEED')"` + `python -m json.tool < <each json>` | ~10s |
| **Per plan commit** — Plan 05 (tests + acceptance) | `python -m pytest` (Gate G4 — first and only pytest run of the phase) | ~5-15s |
| **Phase gate** | All four CONTEXT D-18 gates green + `31.5-VERIFICATION.md` written | n/a |
| **Max feedback latency** | <1s for the per-task sampler · ~15s for the phase-gate full suite | — |

**Critical Nyquist rule:** Pytest runs ONCE in the entire phase, at end of Plan 05. Plans 01–04 sample at *import* level instead. Anti-pattern is mid-strip pytest — cut-only test files yield false signal.
