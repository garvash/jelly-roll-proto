# 03-02-PLAN: Hazard Mechanics & Spike Collision

## Objective
Implement instant-death hazards (spikes) and basic player respawning logic to provide a consequence for failure and define the exploration challenge.

## Context
Phase 1 established core movement, and Phase 2 added the slime. Phase 3 (this wave) introduces environmental hazards. `ENV-01` requirements specify spikes that kill the player.

## Implementation Steps

### Task 1: Hazard Detection in Player
- Update `src/entities/player.py` `move_and_collide` to check for hazards using `self.level_map.is_hazard` (implemented in 03-01).
- Add `self.is_alive` and `self.start_x/y` to `Player.__init__`.
- Implement `Player.die()` which sets `is_alive = False` and triggers a respawn sequence.

### Task 2: Respawn Logic in Game
- In `main.py`, track `self.death_timer`.
- If `player.is_alive` is False:
  - Increment `death_timer`.
  - After ~15 frames, reset player position to `start_x/y` and set `is_alive = True`.
  - Reset `death_timer`.

### Task 3: Visual Death Indicator
- In `Player.draw`, if `not self.is_alive`, change drawing logic (e.g., draw at different color or simple pixel burst).

## Verification Strategy

### Automated Tests
- Create `tests/test_hazards.py`.
- **Test 1:** Move player into a known hazard tile coordinate and verify `player.is_alive == False`.
- **Test 2:** Verify player position resets after death timer expires.

### Manual Verification
- Run `python main.py`.
- Walk into a spike tile.
- Confirm player disappears/flashes and respawns at the start.
