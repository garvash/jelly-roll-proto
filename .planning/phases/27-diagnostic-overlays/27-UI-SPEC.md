# Phase 27 — UI Design Contract (Diagnostic Overlays)

> Visual and interaction contract for Pyxel debug overlays. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Pyxel built-in draw primitives) |
| Preset | not applicable |
| Component library | none — Pyxel `rectb`, `line`, `pset`, `circb`, `circ` |
| Icon library | none — all indicators are geometric primitives |
| Font | Pyxel built-in 4x6 font (used only for toggle status text, not overlay content per D-03) |

---

## Screen Geometry

| Property | Value | Source |
|----------|-------|--------|
| Screen | 320 x 192 px | physics-schema.json |
| Viewport | 320 x 176 px (game area) | physics-schema.json |
| HUD bar | 16 px tall, bottom of screen (y=176..191) | physics-schema.json |
| Tile grid | 16 x 16 px | entity-schema.json |
| Player hitbox | 10 x 14 px | player.py |
| Slime hitbox | 16 x 16 px | slime.py |

Overlays draw in the viewport area (y 0..175). Overlays MUST NOT draw into the HUD bar region (y 176..191) to avoid visual collision with the existing juice/HP display.

---

## Spacing Scale

Pyxel pixel art operates at 1:1 pixel scale. No CSS-style spacing tokens apply. Instead, use these pixel constants:

| Token | Value | Usage |
|-------|-------|-------|
| hitbox_pad | 0 px | Wireframes drawn exactly on entity collision bounds |
| arrow_length | 8 px minimum | Velocity vector arrows — scaled by magnitude, clamped to 8..32 px |
| arrow_max | 32 px | Maximum velocity arrow length to prevent screen overflow |
| blip_radius | 2 px | Coyote/buffer spatial blips |
| blip_fade_frames | 30 frames (0.5s at 60fps) | Duration before blip fully fades |
| breadcrumb_gap | 0 px (every history entry) | Slime trail dots use every entry from history deque |
| dist_circle_width | 1 px | Slime distance threshold boundary circles (drawn with `circb`) |
| status_text_margin | 2 px | Padding for overlay toggle status indicator in top-left corner |

Exceptions: none

---

## Typography

Overlays are pure-visual per D-03. No text readouts in overlays. The ONLY text is a tiny toggle status indicator showing which overlays are active.

| Role | Font | Size | Usage |
|------|------|------|-------|
| Toggle indicator | Pyxel built-in | 4x6 px per char | Top-left corner: "F2 F3 F4 F5" with active keys highlighted |

No other text appears in overlays. Numbers, labels, and readouts are deferred to Phase 28 panel.

## Color Contract (Pyxel 16-Color Palette)

All colors reference Pyxel default palette indices (0-15). Colors are chosen to contrast against the dark cavern tileset (dominated by palette 0 black, 1 dark blue, 5 dark grey).

### F2 — Hitbox Wireframe Overlay

| Element | Palette Index | Pyxel Color Name | Rationale |
|---------|--------------|-------------------|-----------|
| Player hitbox | 8 | Red | High visibility, standard hitbox debug color |
| Slime hitbox | 11 | Green | Distinguishes companion from player |
| Enemy hitboxes | 9 | Orange | Hostile entities — warm warning color |
| Projectile hitboxes | 10 | Yellow | Fast-moving objects need bright color |
| Map entity hitboxes (doors, blocks) | 6 | Light grey | Neutral — static geometry |
| Boss hitbox | 2 | Dark purple | Unique identifier for boss entity |

Draw primitive: `pyxel.rectb(entity.x, entity.y, entity.w, entity.h, color)`

### F3 — Velocity + Frame-Time Overlay

| Element | Palette Index | Pyxel Color Name | Rationale |
|---------|--------------|-------------------|-----------|
| Velocity arrow (horizontal component) | 8 | Red | X-axis velocity |
| Velocity arrow (vertical component) | 12 | Blue | Y-axis velocity (gravity direction) |
| Combined velocity arrow | 10 | Yellow | Resultant vector |
| Frame-time graph background | 1 | Dark blue | Subtle background for graph |
| Frame-time graph line (normal) | 11 | Green | Under budget = good |
| Frame-time graph line (spike) | 8 | Red | Over budget = bad |
| 16.67ms target line | 6 | Light grey | 60fps budget reference |

Velocity arrows: Draw from entity center using `pyxel.line()`. Arrow length = `abs(velocity) * 8`, clamped to range 8..32 px. Arrowhead: 2px chevron at tip using two `pyxel.line()` calls.

Frame-time graph: 64 px wide, 24 px tall, positioned top-right corner at (320-64-2, 2). Rolling window of 64 frames. Y-axis: 0ms at bottom, 33ms at top. Each column is 1 px wide.

### F4 — Input State + Coyote/Buffer Blips

| Element | Palette Index | Pyxel Color Name | Rationale |
|---------|--------------|-------------------|-----------|
| Coyote blip (ground-leave point) | 11 | Green | "Safe" — had ground |
| Jump-press blip (input event point) | 8 | Red | "Action" — player pressed |
| Coyote-to-press connector line | 10 | Yellow | Shows spatial gap between events |
| Jump buffer blip (early press point) | 12 | Blue | Distinct from coyote |
| Buffer-to-land connector line | 14 | Pink | Distinct from coyote connector |
| Active coyote timer indicator | 11 | Green | Small dot under player while timer > 0 |
| Active buffer timer indicator | 12 | Blue | Small dot above player while timer > 0 |

Blip rendering: `pyxel.circ(x, y, 2, color)` — solid circle radius 2 px at the world position where the event occurred. Blips fade by switching palette: full color for 15 frames, then palette 13 (light grey) for 15 frames, then removed.

Connector lines: `pyxel.line(blip1_x, blip1_y, blip2_x, blip2_y, color)` — drawn only while both blips in a pair are still visible.

Timer indicators: `pyxel.pset(player_center_x, player_y + player_h + 1, color)` for coyote (below player), `pyxel.pset(player_center_x, player_y - 1, color)` for buffer (above player). Visible only while the respective timer is > 0.

### F5 — Slime Follow Overlay

| Element | Palette Index | Pyxel Color Name | Rationale |
|---------|--------------|-------------------|-----------|
| Breadcrumb trail (recent, 0-10 entries) | 11 | Green | Fresh trail = bright |
| Breadcrumb trail (mid, 11-20 entries) | 3 | Dark green | Aging trail |
| Breadcrumb trail (old, 21+ entries) | 5 | Dark grey | Stale trail fading out |
| SLIME_MAX_DIST circle | 8 | Red | Danger boundary — teleport if exceeded |
| SLIME_REFORM_DIST circle | 10 | Yellow | Reform/spawn boundary |
| Follow target point | 14 | Pink | Where slime is trying to reach |
| Stuck detection indicator | 8 | Red (flashing) | Flashing X at slime position when stuck |
| Catch-up state indicator | 12 | Blue | Small arrow from slime toward target when in catch-up |

Breadcrumb trail: `pyxel.pset(hx, hy, color)` for each `(hx, hy)` in `slime.history` deque. Color determined by index: 0-10 = palette 11, 11-20 = palette 3, 21+ = palette 5.

Distance circles: `pyxel.circb(player_cx, player_cy, SLIME_MAX_DIST, 8)` and `pyxel.circb(player_cx, player_cy, SLIME_REFORM_DIST, 10)`. Drawn centered on player.

Stuck indicator: When slime velocity magnitude < 0.1 for > 10 consecutive frames, draw a flashing X (alternating frames visible/hidden) at slime center using two crossed `pyxel.line()` calls, 4 px each arm.

### Toggle Status Indicator

| Element | Palette Index | Pyxel Color Name |
|---------|--------------|-------------------|
| Active overlay label | 7 | White |
| Inactive overlay label | 13 | Light grey (dim) |
| Background bar | 1 | Dark blue (50% opacity via checkerboard) |

Position: top-left corner, (2, 2). Format: `F2 F3 F4 F5` in Pyxel built-in font. Active overlays in white (7), inactive in dark grey (13). Background: dark blue checkerboard pattern behind text for readability against any tileset.

## Interaction Contract

### Toggle Behavior

| Key | Overlay | Behavior |
|-----|---------|----------|
| F2 | Hitbox wireframes | Toggle on/off. Independent of other overlays. |
| F3 | Velocity + frame-time | Toggle on/off. Independent of other overlays. |
| F4 | Input state blips | Toggle on/off. Independent of other overlays. |
| F5 | Slime follow | Toggle on/off. Independent of other overlays. |

All four overlays can be active simultaneously. Each F-key is a binary toggle (press once = on, press again = off). Default state on game boot: all off.

F-keys MUST NOT conflict with existing Ctrl+1/2/3 debug toggles in `src/core/debug.py`. F2-F5 are unmodified keypresses (no Ctrl/Shift required).

### Draw Order

Overlays draw AFTER all game entities and AFTER the HUD. Draw order within overlays:

1. F5 slime follow (distance circles are large, should be behind other elements)
2. F2 hitbox wireframes
3. F3 velocity arrows + frame-time graph
4. F4 input blips (topmost — most transient, needs highest visibility)

### Performance Contract

- Overlays MUST NOT modify any gameplay state (position, velocity, timers, HP, etc.)
- Overlays MUST NOT allocate per-frame objects (use pre-allocated buffers for blip history)
- Maximum blip history: 32 entries for coyote/buffer blips (ring buffer)
- Frame-time graph: 64-entry ring buffer (pre-allocated list, not appended)
- All draw calls use Pyxel primitives only (`rectb`, `line`, `pset`, `circ`, `circb`) — no `blt` or image bank access
