self._update_anim_driver()

**Key parity nuance:** apply_physics reads dy/dx and adds gravity. Drill_dive sets dy=DRILL_SPEED in TickResult, FusionManager applies it (`player.dy = result.dy`), THEN apply_physics may add GRAVITY making `player.dy = DRILL_SPEED + GRAVITY`. The v1.3 path bypassed apply_physics entirely during DIVING (the `if/else` branch). To preserve parity, Plan 06 must EITHER:
- (a) Keep an `if self.state == "DIVING":` skip-apply_physics branch in Player.update so drill_dive.on_tick's TickResult.dy survives untouched, OR
- (b) Move apply_physics's gravity branch to NOT apply when fused (early return on `self.is_fused`), OR
- (c) Have drill_dive re-clamp dy AFTER apply_physics — but apply_physics runs after fusion_manager.tick, so drill_dive can't intercept.

**Picked: (a) — keep `if self.is_fused: skip apply_physics` branch in Player.update.** This is the MINIMAL change. The branch becomes:
```python
if self.game:
    self.game.fusion_manager.tick(self, slime, dt=1.0)
if not self.is_fused:
    self.apply_physics()                                  # gravity, friction, etc.
self.move_and_collide(slime)
```

This preserves v1.3 drill parity (no gravity stacking) while still letting drill_dive.on_tick own the dy/dx assignment via TickResult.
